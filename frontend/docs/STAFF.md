# Staff Feature

Introduce staff as scare performers that amplify fear in attractions.

## Overview

Staff are abstract resources (counts, not entities) that players hire and assign to haunts. Assigned staff amplify fear generated by scare rooms, creating a risk/reward dynamic: more staff means scarier haunts, but also higher upkeep and potential for visitor panic deaths.

## Design Decisions

### Staff Are Abstract

Staff have no:
- Individual IDs or entities
- Spatial position or movement
- Schedules or shifts
- Morale, health, or fatigue

They are pure counts in game state. This keeps implementation simple and avoids micromanagement.

### Fear Only

Staff affect **only** fear generation in scare rooms. They do not:
- Reduce queues or congestion
- Affect happiness
- Speed up visitors
- Work on the midway

### Diminishing Returns

Staff bonus uses square root scaling to prevent linear power growth:

```ts
staffBonus = floor(BASE_STAFF_FEAR_BONUS * sqrt(staffAssigned))
```

| Staff | Bonus (BASE=10) |
|-------|-----------------|
| 1     | +10 fear        |
| 2     | +14 fear        |
| 3     | +17 fear        |
| 4     | +20 fear        |

This makes the first staff impactful while preventing 4 staff from being 4x deadlier.

## Constants

```ts
// Economy
export const STAFF_HIRE_COST = 50;         // ~5 admissions to recoup
export const STAFF_UPKEEP_PER_TICK = 0.5;  // ~25% of a hallway

// Capacity
export const HAUNT_STAFF_CAP = 4;          // Max per haunt regardless of size

// Fear bonus
export const BASE_STAFF_FEAR_BONUS = 10;   // sqrt scaling applied
```

### Economy Rationale

- **Hire cost ($50)**: 5x admission fee. Not trivial, but affordable early. Takes ~5 visitors to "pay off" the hire.
- **Upkeep (0.5/tick)**: A typical small haunt (3 hallways + 1 scare) costs ~5/tick. Two staff add 1/tick = 20% increase. Pressure accumulates, doesn't spike.
- **No refund on firing**: Commitment matters. Can't freely swap staff between haunts.

## Architecture

### State Shape

Add to `GameState` in `types.ts`:

```ts
// Staff state
staffHired: number;                           // Total hired
staffAssignments: Record<string, number>;     // attractionId -> assigned count
```

No individual staff objects. Just counts.

### Derived Values

Some values are computed, not stored:

```ts
// Unassigned staff
const unassigned = staffHired - sum(Object.values(staffAssignments));

// Haunt capacity (per attraction)
const capacity = min(HAUNT_STAFF_CAP, countScareRooms(attraction.grid));
```

### Integration Points

**Upkeep** (`src/core/economy.ts`):

The existing `totalUpkeepPerTick` function sums room upkeep. Add staff upkeep:

```ts
const staffUpkeep = state.staffHired * STAFF_UPKEEP_PER_TICK;
return roomUpkeep + staffUpkeep;
```

**Fear application** (`src/core/visitors/applyRoomEmotionEffects.ts`):

When a visitor enters a scare room in an attraction:

1. Get `staffAssigned` for that attraction
2. Calculate bonus: `floor(BASE_STAFF_FEAR_BONUS * sqrt(staffAssigned))`
3. Add bonus to base scare fear delta
4. Clamp result to fear bounds

This happens **once on entry**, not per tick.

**Capacity calculation** (`src/core/staff.ts`):

```ts
export const getHauntStaffCapacity = (grid: Grid): number => {
  let scareCount = 0;
  for (const row of grid) {
    for (const cell of row) {
      if (cell.roomType === 'scare') scareCount++;
    }
  }
  return Math.min(HAUNT_STAFF_CAP, scareCount);
};
```

### Actions

**hireStaff**:
1. Check `money >= STAFF_HIRE_COST`
2. Deduct cost
3. Increment `staffHired`

**fireStaff**:
1. Check `staffHired > 0`
2. If firing would leave assignments orphaned, unassign first (or reject)
3. Decrement `staffHired`

**assignStaff(attractionId, delta)**:
1. Calculate current assignment and capacity
2. Validate: `newAssignment >= 0`, `<= capacity`, `<= totalUnassigned + current`
3. Update `staffAssignments[attractionId]`

## UI Design

### Staff Panel

Add collapsible panel in HUD or modal:

```
┌─ Staff ──────────────────────┐
│ Hired: 3 / ∞                 │
│ [Hire $50] [Fire]            │
│                              │
│ Unassigned: 1                │
│                              │
│ ─ Assignments ─              │
│ Dev Haunt 1    [2/3] [+][-]  │
│ Dev Haunt 2    [0/2] [+][-]  │
└──────────────────────────────┘
```

- Show hired count (no global cap, so "∞")
- Hire button disabled if no money
- Fire button disabled if no staff
- Per-haunt row shows assigned/capacity
- +/- buttons for assignment
- Disable + if at capacity or no unassigned
- Disable - if at zero

### Visual Indicators

On portal/attraction tiles:
- Badge or icon showing staff count
- Intensity scales with assignment (glow, color shift)
- Could reuse existing room highlight system

## Edge Cases

1. **Fire with assignments** - Must unassign first, or auto-unassign from last-assigned haunt
2. **Delete haunt with staff** - Staff become unassigned (future: if demolition added)
3. **Capacity changes** - If scare room demolished (future), excess staff become unassigned
4. **Zero scare rooms** - Capacity is 0, cannot assign staff

## Lifecycle

**newGame:**
- `staffHired = 0`
- `staffAssignments = {}`

**fail:**
- Staff state is ignored (game over)
- No cleanup needed beyond state reset

## Scope Lock

Staff in MVP:
- Only affect fear
- Only work in scare rooms
- No movement, schedules, morale
- No happiness effects
- No queue/congestion effects

Future expansions require new tickets.
